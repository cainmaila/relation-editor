# 名詞表

每個名詞：定義＋**為什麼要有它**。來源 PRD §3；與 PRD 不同時以 PRD 為準並更新此檔。

| 名詞               | 定義                                                                                                                                       | 用意（建資料時怎麼用）                                                                                |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------- |
| 節點               | 圖上的物件：設備、空間、客戶、通用節點。**有狀態或讀值的才是節點**，純連接是邊                                                             | 判斷來源裡的東西該不該成節點：線纜、接點若沒有自己的狀態，就不建節點，用邊表示                        |
| 邊                 | 兩節點間**有方向**的關係。A→B：A 出事，追查從 A 展開到 B；B 出事不追到 A                                                                   | 方向就是「影響方向」。方向寫反，找客戶就錯                                                            |
| key                | 節點唯一識別：必填、全圖唯一（含 IDC）、建立後不可改；邊以 key 當起點／終點                                                                | 資料迭代時 key 是對齊的唯一依據，所以不可改。來源沒有穩定編號時，用現場看得懂的名稱當 key，且別含 `>` |
| 名稱               | 顯示名稱：選填、可重複；空白顯示 key                                                                                                       | key 已夠辨識就留空                                                                                    |
| 系統               | 節點第一層分類：空間、電力、空調、網路、消防、CCTV、IDC                                                                                    | 決定節點寫進哪個 `nodes/<系統>.csv`；畫面上可依系統開關                                               |
| 節點類型           | 節點的種類，每種屬於一個系統                                                                                                               | 類型決定它能連什麼邊。見 `types.md`                                                                   |
| 邊類型             | 邊的種類（包含、供電、冷卻、連線、服務、承載、監測），限制哪些類型能連出／連到                                                             | 同兩個節點用不同邊類型，語意不同。見 `types.md`                                                       |
| 通用節點           | 不屬於任何系統，用來整理**跨系統**的關係：多系統的東西都跟同一件事有關時，各自連到它，而不是兩兩互連。它那端不受邊類型限制，另一端照常檢查 | 來源出現「這幾個東西一起負責某範圍／某件事」時用。避免 N 個系統兩兩互連                               |
| 屬性               | 節點與邊除固定欄位外可帶任意自由屬性（額定電流、路別、總 U 數…）                                                                           | 來源有但沒對應欄位的資訊放這。CSV 多一欄即可                                                          |
| 確認狀態           | 邊的屬性：`已確認`＝有資料來源；`推定`＝依圖面或位置推導                                                                                   | 讓使用者區分「有憑據」與「猜的」。拿不準一律 `推定`                                                   |
| 方向（單向／雙向） | 預設取自邊類型，逐條可改；`雙向` 欄填「是」或留空。目前全部單向                                                                            | 雙向＝兩頭都會追查到對方。除非來源明說，不要填                                                        |
| 根節點             | 整張圖以 `TPKC 大樓` 為根                                                                                                                  | 所有節點最終都該不看方向連到它                                                                        |
| 未處理節點         | 不看方向、連不到根節點的節點                                                                                                               | 代表還沒整理進主圖。**暫時允許**，但要回報數量                                                        |
| 無客戶路徑         | 沿方向走不到任何客戶的節點（客戶本身除外）                                                                                                 | 代表關係鏈有**缺口**，是資料還缺什麼的線索，與「未處理」是兩回事                                      |
| 找客戶             | 從某節點出發，只沿邊的方向往下走，列出走得到的客戶                                                                                         | 這是終極目標的檢驗：任何設備出事都該能列出客戶。不判斷直接／間接、冗餘                                |
| IDC 維護關係       | 機櫃→機框→主機、主機→機框（承載）、機框→客戶，由 IDC機櫃配置管理維護，編輯器唯讀                                                           | 來源若含這些，視為 IDC 資料放 `idc/`；機櫃屬空間系統，是兩份資料的接點                                |
| 設定與圖           | 設定＝有哪些系統／類型；圖＝實際節點與邊                                                                                                   | 新增類型是改設定（`config.ts`），不是改資料，要先問使用者                                             |
