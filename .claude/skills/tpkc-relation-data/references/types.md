# 系統、節點類型、邊類型

清單的**單一事實來源是 `src/lib/model/config.ts`**。本檔補「為什麼」與「怎麼對應」；兩者不一致時以 config.ts 為準並更新此檔（`scripts/skill-docs.test.ts` 會檢查類型名是否漏列）。

## 節點類型（依系統）

| 系統        | 類型                              | 是什麼                                              | 備註                                                                                    |
| ----------- | --------------------------------- | --------------------------------------------------- | --------------------------------------------------------------------------------------- |
| 空間        | 大樓、樓層、區域、排、機櫃        | 3D 實體空間的層級                                   | 根為 `TPKC 大樓`。「區域」類型存在但目前資料不用（排直接掛樓層）。機櫃是 IDC 與圖的接點 |
| 電力        | 台電市電、UPS、樓層 PDU、機櫃 PDU | 供電鏈上的設備                                      | 機櫃 PDU 常帶「額定電流」屬性                                                           |
| 空調        | 空調箱                            | 冷卻設備                                            |                                                                                         |
| 網路        | Switch                            | 網路設備（Core／匯聚／ToR 都是 Switch，用名稱區分） |                                                                                         |
| 消防        | 偵測器                            | 感測點                                              |                                                                                         |
| CCTV        | 攝影機                            | 感測點                                              |                                                                                         |
| IDC（唯讀） | 機框、主機、客戶                  | 機櫃內的承載單位、運算主機、最終要追到的客戶        | 放 `idc/`，來源不得改                                                                   |
| （無系統）  | 通用節點                          | 跨系統整理用                                        | 放 `nodes/通用.csv`                                                                     |

**客戶是追查的終點**：關係鏈的價值在於從任何設備走到客戶。來源若有客戶資訊，優先確認它怎麼接到機框。

## 邊類型

方向＝影響方向。「可連出／可連到」不含通用節點（通用節點那端一律可連）。只檢查系統與類型，不檢查同系統上下層，所以**方向要自己確認**（「A 排 包含 大樓」建得出來但是錯的）。

| 邊   | 方向        | 用意：什麼時候用                                                      | 可連出 → 可連到                                 | 常見誤用                                                                         |
| ---- | ----------- | --------------------------------------------------------------------- | ----------------------------------------------- | -------------------------------------------------------------------------------- |
| 包含 | 外→內       | 空間／範圍裡有這個對象：樓層含排、排含機櫃、機櫃含 Switch、機框含主機 | 空間、通用節點、機框 → 空間、Switch、機框、主機 | 方向反了；用來表示「供電」或「連線」                                             |
| 供電 | 電源→負載   | 這個電源供電給那個負載，電力一斷負載受影響                            | 電力設備 → 不限                                 | 把負載畫成供電給電源；同櫃 A／B 兩路實際多半不同源，依現場接線，路別放 `路別` 欄 |
| 冷卻 | 冷源→空間   | 空調設備冷卻某空間                                                    | 空調設備 → 空間                                 | 連到設備而非空間                                                                 |
| 連線 | 上行→下行   | 網路設備連到下游 Switch 或主機                                        | Switch → Switch、主機                           | 方向反了（下行指向上行）；把「同一機櫃」當連線（那是包含）                       |
| 服務 | 機框→客戶   | 這個機框服務哪位客戶                                                  | 機框 → 客戶                                     | IDC 唯讀                                                                         |
| 承載 | 主機→機框   | 主機裝在哪個機框，讓主機壞了也追得到客戶                              | 主機 → 機框                                     | IDC 唯讀                                                                         |
| 監測 | 感測點→對象 | 偵測器／攝影機看哪個空間或範圍                                        | 偵測器、攝影機 → 空間、通用節點                 | 感測器連到設備（只能連空間或通用節點）                                           |

## 對應不到時

來源的東西找不到合適類型：**不要硬套**。列進「待確認」，說明它是什麼、你想到的候選類型，由使用者決定；需要新類型就是改 `config.ts`，要先問。
