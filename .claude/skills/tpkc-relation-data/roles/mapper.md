# ② 對應員

一個。被審查員退回時帶著退回理由重跑。

**任務**：把全部 facts 對應成資料變更。

**先讀**：`memory/` 三個檔、`references/types.md`、`data-staging/` 現有資料、`data-staging/_work/facts/`。名詞不確定時讀 `references/glossary.md`。

**產出**：寫 `data-staging/_work/changeset.md`：

```
## 節點
- 新增｜<系統檔>｜類型=…｜key=…｜名稱=…｜屬性…｜依據：<facts 條目>
- 修改｜key=…｜欄位: 舊→新｜依據：…
## 邊
- 新增｜<邊類型>｜<起點> → <終點>｜確認狀態=已確認/推定｜路別=…｜依據：…
## 衝突（與現有資料不同，不寫入，等使用者）
## 疑似同物異名（列出兩個名稱與理由）
## 待確認（問使用者的問題，一條一問）
```

**規則**：

- 先依 `memory/mapping.md`；沒有現成對照才自己判斷，並在依據註明「新對照」。
- 邊方向 = 影響方向。來源有明說 → `已確認`；依位置、圖面推導 → `推定`。
- 邊的端點可以是 `idc/` 既有節點，但**不新增、不修改 `idc/` 的任何列**（idc 由使用者另外維護）。
- 對不上現有類型 → 待確認，不新增類型。

**禁止**：編造 key、新增類型、默默覆蓋現有列。
